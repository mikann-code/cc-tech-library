## 概要

配列をランダムに並べ替える定番の Fisher–Yates シャッフルを、写経ではなく理解するために 1 行ずつ分解した記録。ループの初期値（`length - 1`）・終了条件（`i > 0`）・乱数レンジ（`i + 1`）がそれぞれ何を担うのか、そして `sort(() => Math.random() - 0.5)` で代用してはいけない理由を整理する。

## サンプルコード

```ts
function shuffle<T>(items: readonly T[]): T[] {
  const copy = [...items];
  for (let i = copy.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [copy[i], copy[j]] = [copy[j], copy[i]];
  }
  return copy;
}
```

引数を `readonly T[]` にしてスプレッドで浅いコピーを作り、入れ替えはコピーにだけ行うので呼び出し元の配列は変化しない（非破壊）。計算量は O(n)、追加メモリはコピー分の O(n)。

## ポイント

- **`copy.length - 1` は「最後の要素のインデックス」**。添字は 0 始まりなので `copy.length` を触ると範囲外で `undefined`。より本質的には `i` は「これから確定させる席」であると同時に「まだ確定していない範囲 `[0..i]` の右端」で、未確定範囲は最初は配列全体だから `length - 1` から始まる。
- **`i > 0` で止めるのは、最後の 1 つに選ぶ余地がないから**。`i = 1` の周回を終えると未確定の席も要素も 1 個だけになり自動的に確定する。`i >= 0` でも結果は正しいが、`i = 0` は `Math.random() * 1` が必ず `0` になり自分自身との swap になるだけの無駄な 1 周。
- **`j` は乱数が決める「出所」、`i` はループが決める「行き先（席）」**。swap で席 `i` から押し戻された要素は未確定範囲 `[0..i-1]` に残り、次回以降も抽選対象であり続ける。捨てられる要素がないので要素数と席数が一致したまま進む。
- **乱数に掛けるのは `i` ではなく `i + 1`**。`Math.random()` は `[0, 1)`（1 を含まない）を返すので、`(i + 1)` を掛けて `Math.floor` すると `0` 以上 `i` 以下が等確率になる。`i` を掛けると `j === i`（その要素が動かずその場に残るケース）が起きなくなり、並びに偏りが出る（有名なバグパターン）。
- **`[...items].sort(() => Math.random() - 0.5)` で代用しない**。比較関数が一貫性を欠く（同じ 2 要素でも呼ぶたび結果が変わる）ため、実装依存かつ偏った並びになり一様なシャッフルにならない。React でシャッフル順をマウント時に 1 回だけ固定したいなら `useState(() => shuffle(source))` の遅延初期化を使う（`() =>` を付けないと毎レンダーで `shuffle` が実行される）。
